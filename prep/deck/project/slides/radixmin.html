Radix sort: сортировка без сравнений

64-битный ключ — это 8 байт. Раскладываем числа по «корзинам» младшего байта, сохраняя порядок внутри корзины, потом следующего… 8 проходов, и всё отсортировано.

На схеме для наглядности 8-битные ключи и полубайт: 2 прохода по 16 корзин, показаны непустые. Внутри корзины порядок прихода сохраняется — поэтому после последнего прохода всё отсортировано.

Линейно, но с константой

O(N · число байт): проход подсчёта и 8 проходов раскладки — без единого сравнения.

Нужен буфер на N

Раскладывать «на месте» нельзя — второй массив того же размера. Одна аллокация, дальше два плотных буфера.

Только «цифровые» ключи

Целые, фиксированной длины. Для строк и объектов с компаратором — не подходит. Дальше тот же unique.

LSD radix из бенчмарка: 8 проходов по байту (256 корзин), счётчики 8×256 за один предварительный проход, проход пропускается, если все ключи в одной корзине, буфер на N · после — тот же unique + erase

Backup, вне тайминга. В основном потоке radix — одна фиолетовая полоса на flat.
Q&A: «Как работает radix?» или «Почему не radix везде, раз он быстрее всех?»
Ответ: поразрядная сортировка вообще не сравнивает числа — а значит, на неё не действует нижняя граница N log N для сортировок сравнением. Ключ — восемь байт. Берём младший байт, раскладываем числа по 256 корзинам, как письма по ячейкам на почте; внутри корзины порядок прихода сохраняется. Потом следующий байт, и так восемь раз — после последнего прохода всё отсортировано. На схеме то же самое на 8-битных ключах и полубайтах: два прохода. Это линейно: проход подсчёта и восемь проходов раскладки, без единого сравнения и без ветвлений на данных. Цена: буфер того же размера, и на тысяче элементов девять проходов и счётчики 8×256 дороже десяти сравнений на элемент — на малых N radix проигрывает. И работает только для «цифровых» ключей — целых фиксированной длины; строкам и объектам с компаратором нужен другой инструмент. Дальше — тот же unique.
Под рукой:
— Схема: вход 0x1A 0x03 0x2A 0x11. Проход 1, младший полубайт: ·1 → 0x11; ·3 → 0x03; ·A → 0x1A, 0x2A (в порядке прихода). После: 0x11 0x03 0x1A 0x2A. Проход 2, старший: 0· → 0x03; 1· → 0x11, 0x1A; 2· → 0x2A. После: 0x03 0x11 0x1A 0x2A.
— «Почему не radix везде?» (qa C13): нужны целые ключи фиксированной длины, буфер ещё на N (8 МБ на миллионе — память, которую считает jetsam) и достаточно большой N. При малой доле уникальных radix проигрывает хешу.
— Проходов (cpp.md §7): случайные 64-битные — 8; плотные rowid — 3; случайные меньше 2^32 — 4. Серии доклада — худший случай и для radix.
— M2 Pro, userInitiated, N = U = 2^20: radix 6,9, flat 11,7, sort 19,9 нс/эл. x86, независимый повтор (bench.md E1): radix вровень с flat (40,8 и 42,6 нс/эл), а не быстрее всех; абсолютные наносекунды x86 со сцены не называть.
