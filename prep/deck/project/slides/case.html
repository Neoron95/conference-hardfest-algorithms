Человек вышел из метро, приложение ожило. Локально лежат id записей из SQLite. С сервера пришла дельта с дублями: ретраи, перекрытия страниц. Нужен массив без повторов.
[щелчок] Три детали — три чеховских ружья. Первое: локальные id уже отсортированы. [щелчок] Второе: ключ — 64-битное число. [щелчок] Третье: работает всё это в Task(priority: .utility). По-человечески — «не срочно».
Миллион — верхняя граница теста: у долгоживущих аккаунтов бывают сотни тысяч.
Оговорка: в замерах id случайные, а rowid идут подряд. На таких стандартной хеш-таблице везёт: на x86 она обгоняет сортировку в полтора с лишним раза. Ответ для них — в третьем раунде.
Как убрать повторы? Способов два.
Если отстаю (−15 с): Выбросить фразу про размеры: она на экране. Оговорку про rowid не выбрасывать, сжать до «В замерах id случайные; на плотных rowid хешу везёт — ответ для них в третьем раунде».
Под рукой:
• Плотные id: std::hash для целых — тождество, коллизий ноль. x86, 1M, U = N/2 (bench.md E7): unordered_set ускоряется в 1,65 раза и обгоняет сортировку в 1,7 раза (52,8 против 87,8; libc++ 53,3 против 89,8), а на случайных id там ничья. При U = N вся операция быстрее в 4,7 раза (320 → 68 нс/эл, cpp.md §6). Radix на плотных — 3 прохода вместо 8. Ответ: «Случайные выбраны, чтобы раскладка не зависела от удачи. Для rowid кандидат лучше обоих — слияние, раунд 3; ему всё равно, какие id».
• Id с нулевыми младшими битами в libc++ после reserve(2^k) занимают малую долю ячеек: при шаге 1024 — 64 ячейки из 65 536, цепочки по 1024, вставка медленнее в 70 раз; при шаге 2^20 — одна цепочка, в 1500 раз (cpp.md §6).
• «Миллион на телефоне — кому это надо?» Почти никому, так и сказано; цена на prod посчитана на полумиллионе. Task и QoS: Task(priority: .utility) исполняется на кооперативном потоке с QoS utility (0x11 в исходниках Swift); в бенчмарке QoS ставится через pthread_set_qos_class_self_np. Если экран ждёт await task.value, приоритет задачи поднимут до ожидающей.
