## Исходники

- `reference/first_five.pptx` и `.pdf` — только первые пять слайдов пользовательского референса.
- `reference/first_five.json` — извлечённый видимый текст и заметки. `provenance.json` хранит контрольную сумму исходного My.key.
- `slides/` — HTML версии V8 с обновлёнными элементами и заметками первых пяти тем.
- `notes/z_keynote_v9.json` — авторский текст, который переопределяет первые пять тем при сборке сценария.
- `deck_v9.json` — порядок и контрольные суммы готового файла.

Сборка через `../pptx/build_v9.sh`: JavaScript/Artifact Tool готовит редактируемый рабочий черновик. Затем `assemble_v9.py` применяет точечные правки к исходному пакету V8, сохраняя медиа, шрифты и временные деревья. Он проверяет совпадение текста с референсом и неизменность всех частей вне заданных правок. Финализатор проверяет структуру, геометрию и импорт точного итогового файла.

```bash
export RUNTIME_NODE='/Users/nagornov/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node'
export RUNTIME_PYTHON='/Users/nagornov/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3'
export NODE_PATH='/Users/nagornov/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules'
export PRESENTATIONS_SKILL_DIR='/Users/nagornov/.codex/plugins/cache/openai-primary-runtime/presentations/26.1007.11041/skills/presentations'
bash prep/deck/pptx/build_v9.sh /absolute/workspace/path/prep/deck/hardfest2026_deck_v9_rebuild.pptx
```

Выходной PPTX должен иметь новое имя внутри рабочего репозитория. PDF выпускается из статичного рендера основной части. Временные файлы и отчёты находятся в игнорируемом `prep/.v9-build/`.

V8 и предыдущие версии сохранены. Работа и коммиты выполняются локально по уточнению пользователя. My.key на рабочем столе не изменялся.
