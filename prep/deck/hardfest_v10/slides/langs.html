Та же строчка в вашем языке делает другую работу. [щелчок] В C++ вектор хранит числа. В Python список хранит указатели на объекты, в Java — ссылки на Long. Сортировка такого списка — это уже прыжки по указателям: тот же квест, что у узловой таблицы.
[щелчок] Проверил: в Python на миллионе случайных id set быстрее sorted в пять раз. Ровно наоборот, чем в C++, — потому что сортировка там стала узловой, а set в Python плоский.
[щелчок] И классическая ставка. Отсортированный список, десять тысяч элементов, вставляем новые по месту. Связный список — вставка за один шаг. Вектор — сдвиг хвоста. Кто быстрее? [пауза 3 с]
[щелчок] Вектор. В сто семьдесят раз. Сдвиг — это лента и курьеры, список — коробки по одной. Страуструп показал это в 2012-м; с тех пор разрыв только вырос.
Язык не меняет физику — он меняет, где лежат байты. А теперь вернёмся к задаче: часть данных у нас уже готова.

Источники и условия
Python 3.13, 1M случайных 64-битных int, медианы (bench/deep/langs/results/py_dedup.csv): sorted + unique 711, set 142, list(set) 221, np.unique 825, numpy sort + маска 16 нс/эл (плоский массив возвращает сортировке победу); int-объект 36 Б, set 32 Б на ключ без объектов. Контроль механизма на C++ (cpp_ptrsort.csv): сортировка через указатели на разбросанные объекты 470–570 против 191 нс/эл по значениям. Список против вектора (cpp_listvec.csv, вставка в позицию с бинарным поиском, затем удаление): N = 10K — 20,3 мкс против 0,12 на вставку (×170); 100K — 501 против 4,8 (×100). Java HashSet<Long> — два объекта на ключ, ≈61–64 Б (beyond.md §2.1); Kotlin distinct() — LinkedHashSet. Go и Rust — плоские Swiss-таблицы, sort безветвенный (pdqsort/ipnsort) — не мерил. Java/Go/Rust — не измерено.
