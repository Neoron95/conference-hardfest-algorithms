Слева вектор, наш массив чисел: ключи рядом, по восемь байт. В замере std::sort и unique работают на этом буфере, отдельный узел им не нужен.
[щелчок] Справа узловая таблица. Массив ячеек хранит адреса отдельных узлов. По адресу находим узел: ключ, следующий адрес, служебные данные. Если случилась коллизия, адрес следующего узла узнаём только после чтения текущего.
[щелчок] Каждый новый ключ — отдельное выделение памяти. На миллионе — миллион выделений, потом миллион освобождений. Узлы существуют по причине: стандарт обещает, что ссылки на элементы переживут рост таблицы. Для временного множества мы платим за гарантию, которой не пользуемся.
[щелчок] Счётчик подтверждает: на каждый элемент сортировка промахивается мимо ближайшего кэша меньше раза, узловая таблица — почти три. Вчетверо чаще. Теперь — сколько стоит один промах.

Источники и условия
Промахи L1 на элемент: Xeon VM, cachegrind, N = 2^20, U = N/2 (counters.md §2, D1m). Размер узла: libc++ 24 Б → 32 Б у malloc; libstdc++ 16 Б → тот же чанк 32 Б. Ссылки переживают rehash, итераторы — нет. Детальные счётчики аллокаций — backup allocs.
