Дело не в языке, а в том, как устроена таблица. Узлы, как у unordered_set, есть в Java: HashSet — это узлы HashMap, да ещё упакованный Long. А Swift Set, Go с версии 1.24 и Rust — плоские таблицы, как наша flat. Python set тоже плоский, но каждое число в нём — объект.
Это по исходникам, языки я не мерил — множители из C++ не переносите. Но фон и E-ядро касаются любого языка: там даже плоская таблица проиграла сортировке вдвое. Проверяйте свой вариант на своём устройстве.

Подсказки
• Swift Set: открытая адресация, хеш — SipHash со случайным сидом (дороже, чем в C++); sort() в Swift — своя сортировка, не std::sort.
• Kotlin distinct() — это LinkedHashSet: узлы.
• Python мерили только на облачном Xeon: set на миллионе id в 5 раз быстрее sorted — наоборот, чем в C++: сортировка ходит по указателям на объекты.
• Если спросят «а Android / NDK?» — там та же libc++, unordered_set тоже узловая; ядра и фон решает система и вендор. Не мерили.
