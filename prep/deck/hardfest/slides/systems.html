Под рукой:
• Крупные отношения — исходные результаты колоды при N = U = 2^20. x86 ×2,07 — пилот, исходные абсолютные 70 и 146 нс/эл округлены. Независимый повтор bench E1: ×3,1 с libstdc++, ×2,9 с libc++, вывод по направлению тот же. Не выдавать пилот за повтор.
• Строка x86 при U = N/2 — независимый повтор E2: sort впереди при N = 16 и от 2M; 1M близко, от 64 до 512K хеш или близко. При N = 16 увеличение пула снимает часть обучения: выигрыш sort ×1,75, не ×4 (E2b). Поэтому числа малого N — свойство конкретного харнесса.
• M2 Pro/Linux — VM 4 vCPU; физическое ядро под vCPU выбирает хост. Порог и отношение взяты из исходного systems; не объяснять VM как отдельный тип P/E.
• Mac/macOS — исходные userInitiated данные. На 1M возможен диапазон ×1,1–1,3 между сессиями. iPhone — исходная системная серия userInitiated; не смешивать её с utility из x33.
• iPhone 14 Pro, A16 Bionic. Версия iOS и мобильные сырые данные не сохранены в доступных материалах исходной серии; размеры кэшей iPhone не подставлять из модели. Время — медианы, числа перенесены из существующей колоды. Соответствие устройства между старыми системными сериями не подтверждается сырыми мобильными файлами; число ×2,53 сохраняется как опубликованный результат колоды.
• Сравниваются системы целиком, одновременно меняются CPU, ОС, компилятор, библиотека и режим. Эти числа не отделяют влияние CPU от остального.
• Swift Task: priority не задаёт executor. Task наследует actor isolation; созданный из MainActor Task с синхронным C++ вызовом может остаться на MainActor. Ожидание через await task.value может повысить приоритет. Замер через Swift Task не выполнялся. Первоисточник: SE-0304, разделы Task priorities, Priority Escalation, Context inheritance: https://github.com/swiftlang/swift-evolution/blob/main/proposals/0304-structured-concurrency.md . Не рекомендовать Task.detached автоматически: сначала определить реальный executor.
