На экране.
Локальные id плюс дельта с сервера → уникальные id. Билды: 1 — локальная часть отсортирована и уникальна; 2 — ключ uint64_t; 3 — несрочная работа, .utility как иллюстрация приоритета.

Говорю.
На устройстве есть локальные id записей. С сервера пришла дельта с повторами: ретраи, перекрытия страниц. Нужен массив уникальных id.

Три свойства публичного примера. [щелчок] Локальная часть уже отсортирована и уникальна. [щелчок] Ключ — шестидесятичетырёхбитное число. [щелчок] Работа несрочная, в режиме utility.

Эти детали пока выглядят фоном. Каждая вернётся и изменит решение. В тестовых сериях id случайные; для последовательных чисел расклад может отличаться. Сначала сравним два привычных способа убрать повторы.
[→ следующий слайд]

Если отстаю (−15 с). «Объединяем локальные id и дельту без повторов. Локальные sorted unique, ключ числовой, работа utility. В сериях случайные id». Три свойства раскрывать по очереди.

Под рукой.
Не отождествлять серверные id с SQLite rowid. Условие «локальная часть sorted unique» относится к публичному примеру и обеспечивает корректность будущего set_union. Пример фоновой работы не выдавать за измерение Swift Task.

Источники и условия.
Самостоятельная упрощённая задача: L sorted unique; D может содержать повторы; числовые id. Отдельные тестовые серии фиксируют другие свойства входа.
