Вход. «Вот несколько разных способов хранить одно множество».

На экране. Существующая классификация контейнеров: узлы, открытая адресация, цепочки в массивах. Это устройство реализаций, не сравнительный бенчмарк языков.

Говорю.
У C++ unordered_set и Java HashSet есть отдельные узлы. В Java числовой ключ Long может добавить объект. Go с версии один двадцать четыре и Rust HashMap используют плоскую организацию.

У Swift и Python открытая адресация, но свои хешеры и представление значений. Число в Python обычно является объектом. В C# цепочки хранятся в массивах: слово «цепочка» ещё не означает отдельную аллокацию на ключ.

Это даёт кандидатов для проверки, а не готовые коэффициенты. Сначала узнаём устройство своего контейнера. Затем ставим вопрос к своим данным и среде. Название set — лишь начало разговора.

Выход. «Представьте тот же диф в вашем языке. Какой комментарий оставили бы коллеге?»

Если пропускаю. Переход platforms → review остаётся из основного сценария.

Под рукой. Конкретные типы, версии и оптимизации влияют на боксинг и аллокации. Не говорить «два объекта всегда». Swift/Python не считать узловыми таблицами. Здесь нет измеренных коэффициентов GC или иных хешеров.
