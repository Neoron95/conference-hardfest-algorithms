ХЕШ ВЫБИРАЕТ ЯЧЕЙКУ

Одна ячейка ещё не означает равный ключ: нужна проверка равенства

Хеш-таблица отвечает на вопрос: встречалось ли такое значение? Берём вход по порядку. Для каждого числа вычисляем хеш — другое число, которое помогает выбрать, где искать. В учебном примере берём остаток от деления на четыре. Реальная функция в замере другая.

Семь даёт остаток три. Идём в ячейку номер три, она пока пуста, сохраняем семь. Эту ячейку называют бакетом: она может вести к нескольким ключам.

Следом приходит три. Остаток тоже три. Это коллизия: разные ключи выбрали один бакет. Но три не равно семи, поэтому сохраняем и три. Ключ — наше исходное значение; номер бакета — лишь адрес для поиска. Один адрес не делает значения одинаковыми.

[пауза 2 с]
Приходит ещё семь. Снова идём в третий бакет, сравниваем полные значения и находим семь. Вот теперь это повтор: новый элемент не создаём. Единицу сохраняем, повторную тройку пропускаем, девятку сохраняем после проверки равенства.

[щелчок] Одного номера бакета недостаточно: повтор определяется равенством полных ключей. На выходе те же четыре разных числа. Только порядок их обхода таблица нам не обещала. Сам дедуп — действие, удаление повторов. Множество — то, какие значения остались. Хеш-таблица — один из способов хранить это множество.

При удачном распределении поиск в среднем короткий. При коллизиях приходится проверять больше кандидатов. Поэтому равенство ключей и качество хеша участвуют в цене каждой вставки.
