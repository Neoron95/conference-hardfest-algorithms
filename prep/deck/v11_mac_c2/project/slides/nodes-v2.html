Посмотрим, как каждый из них ходит по памяти. 

Слева сортировка: обычный массив, ключи лежат подряд по восемь байт. Память приезжает строками, и все они нужны.

[щелчок] Справа unordered_set. Массив ячеек хранит не ключи, а адреса. Каждый ключ живёт в отдельном узле где-то в куче. Чтобы найти ключ: читаем ячейку, по адресу из неё идём в узел, из узла — к следующему. Из строки, где лежит узел, нужен один ключ, остальное — чужое.

[щелчок] Вот главное различие. У сортировки следующий адрес — это текущий плюс восемь байт. Процессор знает его заранее и может запросить данные наперёд. У хеша следующий адрес лежит внутри текущего узла. Пока узел не приехал из памяти, процессор просто не знает, куда идти дальше.

Подсказки
• M2 Pro, 2^20 id, все разные. Промахов L1 на число: sort 0,77, хеш 9,19 — в 12 раз больше; промахов TLB 0,01 против 3,6.
• Узел: в libc++ 24 Б (next, хеш, ключ), в libstdc++ 16 Б; malloc выделяет обоим по 32 Б. Строка кэша: 128 Б на Apple, 64 Б на x86.
• Если спросят „из чего 55 нс хеша?“ — вставки 30,3 нс (55 %), выгрузка 13,5 (24 %), деструктор 11,8 (21 %). Деструктор — тоже обход списка, free на каждый узел.
• Если спросят „почему 13,5 нс на узел, а не ≈115 нс полного промаха?“ — не каждый шаг — промах в память: узел 32 Б, в строке 128 Б их четыре, часть пути в кэше.
