**Речь и заметки:**

Давайте для начала вспомним теорию. Начнём с первого способа: Сортировки. Возьмём шесть чисел.

[щелчок] Внутри std::sort — быстрая сортировка, точнее её доработанная версия, introsort. Берём опорное число, например три, и делим на две части: всё, что не больше трёх, — налево, всё, что больше, — направо.

[щелчок] Дальше то же самое внутри каждой части. Части быстро мельчают: на миллионе чисел — около двадцати уровней деления, и на каждом мы проходим по всем числам, отсюда n log n. И смотрите: одинаковые встали рядом.

[щелчок] Остаётся один проход слева направо: берём число, если оно не равно соседу. Получили один, три, семь, девять. Вся работа — сравнения и перестановки в одном массиве, без лишней памяти.
[→ следующий слайд]

──────────
Подсказки
• Части две. Равные опорному могут попасть в любую из них — тут вторая тройка ушла налево. Ровно так эти шесть чисел делит libstdc++: 3 3 1 | 7 7 9. Три группы (меньше / равно / больше) — отдельный приём для данных с кучей повторов.
• Миллион чисел — около 20 уровней деления: log₂ 1 048 576 = 20. На деле std::sort делает 22–25 сравнений на число, нижняя граница — ≈18,6.
• Маленькие куски досортировываются вставками. Если деление слишком глубокое (в libstdc++ предел 2·log₂N), introsort переходит на пирамидальную сортировку и в n² не скатывается.
• Если спросят „а в других языках?“ — Java для примитивов: dual-pivot quicksort, Python: TimSort, Go: pdqsort (с 1.19), Rust sort_unstable: ipnsort, наследник pdqsort.
• В замере: std::sort, потом std::unique сдвигает уникальные в начало, хвост удаляем erase.

- 3 ≠ 7 → оба

- дубль

- Итог: те же четыре числа, ничего не сортировали

**Речь и заметки:**

Способ B — хеш-таблица. Идея ещё проще.

Таблица — это ряд ячеек, номер ячейки считает хеш-функция. Для примера возьмём остаток от деления на четыре.

[щелчок] Семь — ячейка три. Там пусто, кладём.

[щелчок] Три — тоже ячейка три, а там уже семёрка. Это коллизия. Сравниваем: три не равно семи — число новое, кладём в ту же ячейку, в цепочку. Так делает unordered_set. Есть второй способ — открытая адресация: занято — идём в соседнюю ячейку. Так устроены плоские таблицы, к ним мы ещё вернёмся.

[щелчок] Снова семь: идём в ячейку три, сравниваем с каждым в цепочке — семёрка нашлась, это дубль, пропускаем.
[щелчок] Единица — в ячейку один, вторая тройка — дубль, девятка — к единице. Те же четыре числа, и сортировать ничего не пришлось.

Каждое число — один заход в таблицу, на бумаге это O(n). 

На бумаге победитель понятен. Посчитаем, насколько.
[→ следующий слайд]

──────────
Подсказки
• unordered_set решает коллизии цепочками. Открытая адресация (занято — пробуем следующую ячейку) — у absl::flat_hash_set, Python set и dict, Go map с 1.24, Rust HashMap.
• Если спросят „таблица ведь тоже сравнивает?“ — да, но только с ключами из своей ячейки: в среднем одно-два сравнения на число, а не ≈20, как у сортировки.
• Почему „одно-два сравнения“: по умолчанию max_load_factor = 1 — в среднем не больше ключа на ячейку; при превышении ячеек становится больше (rehash).
• Если спросят „O(1) всегда?“ — нет, в среднем: при плохом хеше все ключи в одной ячейке, дедуп становится O(n²). Для целых std::hash — тождество, ключи, кратные числу ячеек, сталкиваются.
• x mod 4 — учебный хеш. Порядок выгрузки таблица не обещает.

[щелчок] Хеш-таблица — в среднем O(N): на каждое число один заход в таблицу. Посчитать хеш, найти ячейку, сравнить с парой соседей по цепочке.

[щелчок] Двадцать шагов против одного. На бумаге хеш должен выиграть раз в двадцать. [пауза 2 с]
[→ следующий слайд]

──────────
Подсказки
• «≈20» — округление для зала: log₂ 1 048 576 = 20; на деле std::sort делает 22–25 сравнений на число, нижняя граница — ≈18,6.
• Если спросят „откуда пара сравнений?“ — unordered_set держит в среднем не больше ключа на ячейку (max_load_factor = 1).
• Если спросят „так O-большое врёт?“ — нет, оно считает, как растёт число шагов, а цену шага отбрасывает. Это раскроем на слайде про цену шага: на M2 20 шагов по ≈1 нс против одного за ≈55 нс (на Xeon ≈4 против ≈260).
