Та же строчка в вашем языке делает другую работу. [щелчок] В C++ вектор хранит числа. В Python список хранит указатели на объекты, в Java — ссылки на Long. Сортировка такого списка на каждом сравнении идёт по указателю к объекту — каждый шаг стал дорогим.
[щелчок] Проверил на облачном Xeon: в Python на миллионе случайных id set быстрее sorted в пять раз. Ровно наоборот, чем в C++, — потому что сортировка там стала узловой, а set в Python плоский.
[щелчок] И классическая ставка. Отсортированный список, десять тысяч элементов, вставляем новые по месту. Связный список: место ищем проходом по узлам, вставка — один шаг. Вектор: место ищем проходом по массиву, потом сдвигаем хвост. Оба O(n) на вставку. Кто быстрее? [пауза 3 с]
[щелчок] Вектор. В двадцать восемь раз — при том же линейном поиске. Проход по массиву и сдвиг хвоста — чтение подряд, процессор подгружает его заранее. Список — зависимые чтения, по одному узлу. А если искать место бинарным поиском, которого у списка не бывает, вектор быстрее в сто семьдесят раз. Страуструп показывал этот опыт ещё в 2012-м.
Язык не меняет физику — он меняет, где лежат байты. А теперь вернёмся к задаче: часть данных у нас уже готова.

Источники и условия
Python 3.13, 1M случайных 64-битных int, медианы (bench/deep/langs/results/py_dedup.csv): sorted + unique 711, set 142, list(set) 221, np.unique 825, numpy sort + маска 16 нс/эл (плоский массив возвращает сортировке победу); int-объект 36 Б, set 32 Б на ключ без объектов. Контроль механизма на C++ (cpp_ptrsort.csv): сортировка через указатели на разбросанные объекты 470–570 против 191 нс/эл по значениям. Список против вектора (cpp_listvec.csv, listvec.cpp; строим отсортированную последовательность из N случайных int, затем удаляем): list — линейный поиск по узлам + O(1) вставка; vector — линейный поиск + сдвиг; vector_binary — lower_bound + сдвиг. N = 10K: 20 312 / 715,5 / 117,9 нс на вставку → ×28 при одинаковом поиске, ×172 с бинарным; 100K: 501 / 24,2 / 4,8 мкс → ×21 / ×104. Машина — облачный Xeon агентов 10.10 (какая из двух VM — в логах не записано). Java HashSet<Long> — два объекта на ключ, ≈61–64 Б (beyond.md §2.1); Kotlin distinct() — LinkedHashSet. Go и Rust — плоские Swiss-таблицы, sort безветвенный (pdqsort/ipnsort) — не мерил. Java/Go/Rust — не измерено.
