Все id разные, как в первом замере: миллион узлов, и сортировка впереди почти втрое. А если разных только один процент — впереди уже хеш, больше чем втрое: узлов всего десять тысяч, они целиком помещаются в кэш.

Второе условие — что мы обещаем на выходе. Нужен отсортированный результат — хешу приходится ещё сортировать ключи, и сортировка впереди в полтора раза. Старый код из дифа возвращал отсортированный массив, а новый молча это изменил. Нужен порядок первого появления — наоборот: хеш просто идёт по входу, а сортировке приходится восстанавливать порядок. Хеш впереди больше чем втрое.

Фраза «без повторов» — это несколько задач. Прежде чем выбирать алгоритм — уточнить: сколько разных и какой порядок обещан. Это порядок на выходе. А какой порядок уже есть на входе?

Под рукой
• Без щелчков: всё видно сразу, голосования нет. Собран из трёх слайдов: share-q, share, outcontract (скрыты в конце колоды). На слайде только победитель и отношение — строки из разных серий, наносекунды между строками не сравнивать.
• Доля разных — M2 Pro, P-ядро, N = 2^20 (m2/E3.csv): 1 % — sort 11,6, uset 3,47 → ×3,35; 10 % — 18,1 / 8,0 (хеш ×2,3); 50 % — 21,5 / 25,4 (sort ×1,18); 100 % — первый замер (E1) 19,3 / 55,2 → ×2,86. 10 тыс. узлов по 32 Б ≈ 330 КБ.
• flat в той же серии (если спросят «почему не flat»): 1 % — 4,2 (unordered_set даже чуть быстрее), 10 % — 7,4, 50 % — 16,5 (flat быстрее сортировки ×1,3), 100 % — 18,6 (ничья).
• Контракт — отдельная, старая серия M2/libc++, U = N/2 (cpp.md §9): порядок любой — sort 20,2 / хеш 22,6 (близко); отсортированный — 20,2 / 32,6 (sort ×1,6); первое появление — 74,6 / 22,0 (хеш ×3,4). Первое появление для sort — пары (ключ, индекс) и вторая сортировка; с битовой маской на x86 на 25–30 % быстрее, хеш всё равно впереди. Новым харнессом не перемерена; flat и Xeon/iPhone в ней нет.
• «Любой порядок» = любой при каждом запуске: плоская таблица, Set в Swift и map в Go меняют порядок обхода от запуска к запуску — скрытое требование живёт в следующем этапе или в тесте. Kotlin distinct() — LinkedHashSet, порядок первого появления по контракту.
• iPhone P: 1 % — 11,8 / 3,5; 100 % — 20,0 / 56,4. CI (Xeon E3): 1 % — 63,3 / 7,9, хеш ×8; 100 % — sort ×3. При 10 % хеш выигрывает почти везде (THREE_MACHINES.md §3), кроме E-ядер на 1–4M.
