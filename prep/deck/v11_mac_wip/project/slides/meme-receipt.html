Быстрое, но неправильное решение
в турнире не участвует

Уточним секундомер. Вход готов, на выходе нужен массив тех же значений без повторов. Сейчас его порядок не важен.

В таймере вся операция. Для сортировки — sort, unique и обрезка хвоста. Для таблицы — reserve, вставки, выгрузка в массив и уничтожение. Закрывающую скобку тоже включили в счёт. [пауза 2 с]

Свежую копию входа готовим заранее. После замера сверяем результат с эталоном, в том числе в релизе. Быстрое решение с потерянными id к сравнению не допускаем.

Reserve хешу дали намеренно: таблица сразу знает размер и не перестраивается по ходу. Сравниваем нормально написанный код, а не наивный. Теперь — первый замер.

Подсказки
• Копию входа готовим вне таймера, внутри — вся операция, проверка с эталоном — после.
• Чек на слайде показывает границы таймера, а не доли времени по стадиям.
• Если спросят „нечестно включать деструктор?“ — в приложении память всё равно освобождается, а без него спрятали бы заметную часть цены: на M2 выгрузка и деструктор — 13,5 + 11,8 из 55 нс на элемент, на Xeon — 60 + 67 из 237.
• Если спросят „зачем reserve?“ — без него таблица перестраивается по ходу вставок; но при малой доле разных резерв под весь вход раздувает таблицу. Берём N: он известен, а число разных — нет.
