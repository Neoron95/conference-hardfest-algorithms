Уточним секундомер. Вход готов, на выходе нужен массив тех же значений без повторов. Сейчас его порядок не важен.

В таймере вся операция. Для сортировки — sort, unique и обрезка хвоста. Для таблицы — reserve, вставки, выгрузка в массив и уничтожение. Закрывающую скобку тоже включили в счёт. [пауза 2 с]

Свежую копию входа готовим заранее. После замера сверяем результат с эталоном, в том числе в релизе. Быстрое решение с потерянными id к сравнению не допускаем.

Reserve хешу дали намеренно: таблица сразу знает размер и не перестраивается по ходу. Сравниваем нормально написанный код, а не наивный. Теперь — первый замер.

Источники и условия
bench/dedup_bench.cpp и bench/results/summary.md. Копия входа вне таймера, полный alg внутри, проверка после. Базовый контракт: unordered unique. Чек иллюстрирует границы таймера, а не измеренные доли времени стадий.
• «Нечестно включать деструктор?» — в приложении память всё равно освобождается; не включить — спрятать заметную часть цены: на M2 выгрузка и деструктор — 13,5 + 11,8 из 55 нс на элемент (слайд alloc-split-v2, m2/E11_phases.csv); на Xeon — 60 + 67 из 237.
• reserve(N) — не бесплатная галочка: без него таблица перестраивается по ходу вставок, но при малой доле уникальных резерв под весь вход раздувает таблицу. Пример: flat_hash_set, 1% уникальных, M2 — 3,6 нс с reserve(N) против 2,9 без, памяти ×64 (backup reserve; старый харнесс V9 — новым харнессом без reserve не перемерено, с reserve сейчас 4,2 нс, m2/E3.csv). Резервируем под N, потому что N известен, а U — нет.
