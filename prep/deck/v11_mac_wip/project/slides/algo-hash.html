Способ B — хеш-таблица. Идея ещё проще. Те же восемь чисел. Таблица — это ряд ячеек, номер ячейки считает хеш-функция. Для примера возьмём остаток от деления на четыре.

[щелчок] Семь — ячейка три. Там пусто, кладём.

[щелчок] Три — тоже ячейка три, а там уже семёрка. Это коллизия. Сравниваем: три не равно семи — число новое, кладём в ту же ячейку, в цепочку. Так делает unordered_set. Есть второй способ — открытая адресация: занято — идём в соседнюю ячейку. Так устроены плоские таблицы, к ним мы ещё вернёмся.

[щелчок] Восемь — в ячейку ноль, единица — в ячейку один.[щелчок] Семь разных чисел, и сортировать ничего не пришлось.

Каждое число — один заход в таблицу, на бумаге это O(n).  На бумаге победитель понятен. Посчитаем, насколько.

Подсказки
• unordered_set решает коллизии цепочками. Открытая адресация (занято — пробуем следующую ячейку) — у absl::flat_hash_set, Python set и dict, Go map с 1.24, Rust HashMap.
• Если спросят „таблица ведь тоже сравнивает?“ — да, но только с ключами из своей ячейки: в среднем одно-два сравнения на число, а не ≈20, как у сортировки.
• Почему „одно-два сравнения“: по умолчанию max_load_factor = 1 — в среднем не больше ключа на ячейку; при превышении ячеек становится больше (rehash).
• Если спросят „O(1) всегда?“ — нет, в среднем: при плохом хеше все ключи в одной ячейке, дедуп становится O(n²). Для целых std::hash — тождество, ключи, кратные числу ячеек, сталкиваются.
• x mod 4 — учебный хеш. Порядок выгрузки таблица не обещает.
