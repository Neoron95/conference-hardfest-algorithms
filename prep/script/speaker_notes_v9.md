## 17. `nodes` — За словом «вставка» стоит память

Слева вектор, то есть наш массив чисел: ключи рядом, по восемь байт. В замере std::sort и unique работают на этом уже подготовленном буфере, отдельный узел им не нужен. Учебное слияние на видео использовало дополнительный буфер: это другая реализация.

[щелчок] Справа стандартная узловая таблица. Массив ячеек хранит указатели — адреса отдельных узлов. По указателю находим узел: ключ, следующий указатель, служебные данные. Если случилась коллизия, узнаём следующий адрес только после чтения текущего узла.

[щелчок] Каждый новый уникальный ключ требует отдельного выделения памяти. На миллионе разных ключей это примерно миллион выделений памяти. Потом — примерно миллион освобождений. Поэтому «одна вставка» на бумаге скрывает и аллокатор, и служебные байты, и порядок обхода памяти.

Узлы существуют по причине: стандартная таблица сохраняет ссылки на элементы при росте. Это полезная гарантия. Но если мы только собираем временное множество и сразу его выбрасываем, за гарантию всё равно платим. Следующий вопрос — сколько стоит добраться до этих байтов.

## 18. `language-layout` — Что лежит внутри коллекции

Короткая ставка про знакомую операцию. Добавляем число в динамический список: в конец или в середину. Сколько памяти придётся тронуть? [пауза 3 с]

[щелчок] Сначала посмотрим, что хранится внутри. В C++ vector числовые значения лежат подряд. В Java ArrayList с Long лежат ссылки на объекты. В CPython список целых тоже хранит указатели. Swift Array с UInt64 хранит значения, но разделяет буфер до изменения. А Swift Set уже использует открытую адресацию, рисунок узловой C++ таблицы к нему не переносится.

[щелчок] Добавление в конец обычно делает одну запись. Рост может скопировать буфер. Вставка в середину сдвигает хвост. У Swift изменение общего буфера может сначала создать копию. Одно слово «вставка» скрывает разный объём работы. Дальше именно эту работу и цену чтения памяти будем считать.

## 19. `memory` — Процессор может ждать каждый шаг

Теперь те же два пути в памяти. Цена шага зависит от того, где находятся данные и сколько ожиданий удаётся перекрыть.

[щелчок] Сверху адреса известны заранее. Процессор может держать несколько запросов в работе. Компактный массив тоже помогает: одна строка кэша приносит соседние значения.

Снизу следующий адрес лежит внутри текущего узла. Сначала дождались данных, затем узнали адрес. Кэш сокращает каждое ожидание, а зависимость всё равно остаётся.

[щелчок] Даже одинаковое число промахов может стоить по-разному: ожидания либо накладываются, либо складываются. Сортировка тоже делает сложные обращения. Эта схема объясняет возможность, а долю её вклада нужно измерять отдельно. Посмотрим, как это ограничение видно в машинных инструкциях.

## 36. `cache-path` — Тип ядра и путь данных
