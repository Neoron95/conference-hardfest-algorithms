Представим, что на устройстве есть локальные id записей. Id — просто число, по которому мы узнаём запись. С сервера приходит дельта: новая порция таких чисел. Из-за повторных запросов или пересечения страниц один id может прийти несколько раз.

Три свойства нашей задачи. 
[щелчок] Локальная часть уже отсортирована и уникальна. 
[щелчок] Ключ — шестидесятичетырёхбитное число. 
[щелчок] Работа несрочная, в режиме utility. (Бэкграунда)

Сначала сравним два привычных способа убрать повторы.

### 11. `contract` — ПРАВИЛО: В ТАЙМЕРЕ ВСЯ ОПЕРАЦИЯ
*0:40 · 0 билдов*

**На экране.**
Копия входа до таймера, алгоритм внутри, проверка после. В цену таблицы входят reserve, вставки, выгрузка и деструктор.

**Говорю.**
Уточним секундомер. Вход готов, на выходе нужен массив тех же значений без повторов. Сейчас его порядок не важен.

В таймере вся операция. Для таблицы это reserve, вставки, выгрузка в массив и уничтожение. Закрывающая скобка тоже стоит времени.

### `hashtable` — УЗЛОВАЯ ХЕШ-ТАБЛИЦА: КАЖДЫЙ КЛЮЧ — СВОЙ new

**Заметки для ответа.**
Backup, вне тайминга. В основном потоке его заменил nodes.
Q&A: «Как устроена узловая хеш-таблица?» или «Деление в libc++ дорогое на ARM — может, хеш проиграл из-за него?»
Ответ: хеш-функция превращает ключ в номер ячейки — как библиотечный каталог превращает название в номер шкафа. Ключ 42, посчитали хеш, взяли остаток от деления на число ячеек — вот шкаф; на слайде учебный пример с восемью. Деталь для знатоков: «остаток от деления» в реальных библиотеках разный. libstdc++ держит простое число ячеек и честно делит. libc++ после reserve под степень двойки берёт маску — младшие биты ключа. В моих замерах деления нет: дорого не оно, а узлы. Коэффициент заполнения по умолчанию 1.0 — reserve(N) выделяет N ячеек; без reserve таблица растёт и перевешивает все узлы. Два разных ключа в одном шкафу — коллизия; узловая реализация решает её цепочкой: в шкафу записка, где лежит первая книга, а в книге — где следующая. Цепочки в среднем короткие, отсюда «O(1)». Для целых std::hash — тождество. В libc++ после reserve под степень двойки номер ячейки — это просто младшие биты id. Для моих случайных id это идеально. Для плотных rowid ещё лучше — коллизий нет вовсе. А id с нулями в младших битах соберутся в одну цепочку. Проверьте гистограмму цепочек. У flat_hash_set из второго раунда свой перемешивающий хешер, absl::Hash, — ему тождество не грозит. Самое важное: каждый узел — отдельный кусок памяти, отдельный вызов new. Стандарт требует, чтобы ссылки на элементы переживали рост таблицы, и узлы — привычный способ это выполнить.
━━━━━━━━━━━━━━━━━━━━━━━━

Под рукой:
— Деление в libc++ появляется только при росте без reserve (как в дифе) или при N, не равном степени двойки; reserve(1048576) даёт ровно 1 048 576 ячеек и маску h & (N−1) (cpp.md §2.2). libstdc++ делит всегда, даже на каждом шаге цепочки: хеш в узле не хранится (cpp.md §3).
— Id, кратные 1024, в libc++ после reserve(2^k) заняли 64 ячейки из 65 536, вставка медленнее в 70 раз; кратные 2^20 — в 1 500 раз (cpp.md §6, qa C8).
— Плотные rowid на x86 при U = N: вся операция в 4,7 раза быстрее случайных id (320 → 68 нс/эл). Готовый ответ: «Серии специально на случайных id, чтобы убрать удачу раскладки. Бенчмарк в репозитории — запустите на своих id».
Условия и источники (были в подвале слайда): Упрощённая схема узловых реализаций (libstdc++, libc++) · учебный hash и 8 ячеек · max_load_factor 1.0, std::hash для целых — тождество · стандарт требует, чтобы ссылки на элементы переживали rehash
С экрана убрано: Вставка: посчитать хеш → прийти в ячейку → пройти цепочку → если ключа нет, создать узел. В среднем цепочка короткая, поэтому «O(1) на операцию». Но каждый шаг цепочки — переход по указателю. Номер ячейки: в libstdc++ число ячеек простое — остаток от деления; в libc++ тоже простое, но после reserve(2^k) — степень двойки и маска по младшим битам. Коллизия: 42 и 50 попали в одну ячейку — висят цепочкой (узлы «42 · next», «50 · next»). Каждый узел — отдельный кусок памяти, свой вызов new. Ячейки (бакеты) — массив указателей.

### `twoways` — УДАЛИТЕ ДУБЛИКАТЫ. ДВА СПОСОБА

**Заметки для ответа.**
2:00–2:45. Дедупликация — это те самые три строчки из ревью. Два классических способа. Первый — отсортировать: после сортировки одинаковые id стоят рядом, и один проход их схлопывает. Это O(n log n). Девять бумажных иллюстраций сохранены из существующей колоды. Это визуальные метафоры, их подписи и технические метки остаются редактируемыми. Полные учебные видеодемонстрации sort, hash, radix, merge сохранены в архиве со всеми 22 этапами. Каждый этап содержит один неповторяющийся ролик и удерживает конечный кадр. Перед этапом назвать действие, после движения пояснить результат. Учебная сортировка слиянием использует дополнительный буфер; измеряемый std::sort устроен иначе.
