# HashBench для iPhone — те же замеры, что на Xeon (CI) и Mac

Приложение запускает тот же C++ код (`../dedup_bench.cpp`, `../mac/{probe,mlp,sortfam,alloc}.cpp`) в трёх режимах
QoS: **ui** (userInitiated, P-ядра), **utility** и **background** (на iPhone — E-ядра). Результаты — CSV в
Documents/results/iphone-<дата>/, видны в «Файлах» (На iPhone → HashBench) и уходят одним zip через «Поделиться».
Счётчиков процессора на iOS нет — только время.

## Один раз: сборка и установка (≈15 минут)

```bash
brew install xcodegen               # cmake уже стоит после bench/mac
cd bench/ios
./build_absl_ios.sh                 # 2–4 мин → build/libabsl_ios.a
xcodegen generate                   # → HashBench.xcodeproj
open HashBench.xcodeproj
```

В Xcode:
1. Слева проект HashBench → таргет HashBench → **Signing & Capabilities** → Team: ваш Apple ID
   (Add Account…, бесплатного достаточно). Если Xcode ругается на Bundle Identifier — поменяйте
   `dev.nagornov.hashbench` на любой свой.
2. iPhone по кабелю. На телефоне: Настройки → Конфиденциальность и безопасность → **Режим разработчика** → вкл
   (телефон перезагрузится).
3. Вверху выберите iPhone как устройство и нажмите ▶ (⌘R). Схема уже собирает Release (-O3).
4. Бесплатный аккаунт: при первом запуске iPhone попросит доверять разработчику — Настройки → Основные →
   VPN и управление устройством → ваш Apple ID → Доверять.
5. Когда приложение открылось, остановите его в Xcode (⌘.) и запускайте с домашнего экрана — без отладчика.

## Прогон (≈35–45 минут)

- Заряд ≥ 80 %, **кабель отключить** (зарядка греет), авиарежим, «Энергосбережение» выключено, без чехла,
  комнатная температура.
- В приложении — **«Всё подряд»** (ui → utility → background). Экран не гаснет сам; не блокируйте телефон и не
  переключайтесь в другие приложения — iOS усыпит прогон.
- При перегреве приложение само делает паузы (видно в журнале и в `run.log`).
- Можно по частям: кнопки ui / utility / background; каждый запуск — новая папка.

## Отправить результаты

«Поделиться результатами» → AirDrop на Mac → в Загрузках `hashbench-results.zip` → распаковать в
`bench/mac/results/iphone14pro/` → `git add bench/mac/results/iphone14pro && git commit -m "iPhone results" && git push`.

## Что внутри прогона

| Файл | Что | Режимы |
|---|---|---|
| `env.txt` | модель (`hw.machine`), iOS, кэши P/E, температура, заряд, версия clang | — |
| `probe.csv` | частота ядра, лестница задержек 16 КБ … 1 ГБ | все |
| `E1.csv` | 1M разных id: sort, unordered_set, radix, flat | все |
| `E2.csv` / `E2U.csv` / `E2D.csv` | кривые по размеру: разных половина / все / 10 % — **карта победителей** | все |
| `E11_phases.csv`, `alloc.csv` | фазы хеша, цена аллокатора | все |
| `mlp.csv` | чтения в полёте, окно (nop и add), модель вставки | все |
| `sortfam.csv` | std::sort, pdqsort с ветвлениями и без, radix | все |
| `E8.csv` | локальные отсортированные + дельта: sort, хеш, flat, слияние | все |
| `E4.csv` | порядок входа: случайный / серии / отсортированный | все |
| `E3.csv`, `E5.csv` | доля разных, выученный вход | ui |

Пул входов на больших N меньше, чем на Mac и Xeon (16 для 512K–1M, 8 для 2M–4M вместо 64) — иначе iOS
выгрузит приложение по памяти. На входах больше кэша это на время не влияет.
