# dedup_bench — воспроизведение x86-серий доклада «O(n) проиграл O(n log n)»

Независимая перепроверка x86-цифр из колоды (HardFest 2026, 17.10.2026) на облачной
машине того же типа, что и в колоде: Intel Xeon @ 2,1 ГГц (KVM), GCC 13.3 + libstdc++,
Clang 18.1 + libc++ 18.1, Abseil LTS 20260817.0.

## Что измеряется

Задача из доклада: вектор `uint64_t` с повторами → уникальные значения в том же векторе,
порядок любой, вход можно портить. Участники:

| имя в CSV | реализация |
|---|---|
| `sort` | `std::sort` + `std::unique` + `erase` |
| `uset` | `std::unordered_set<uint64_t>`, `reserve(N)`, вставки, `v.assign(s.begin(), s.end())`, деструктор |
| `radix` | LSD radix 8 проходов × 8 бит: счётчики 8×256 за один предварительный проход, проход пропускается, если все ключи в одной корзине; буфер на N (одна аллокация, без инициализации); затем `unique` + `erase` |
| `flat` | `absl::flat_hash_set<uint64_t>`, `reserve(N)`, дальше как `uset` |
| `merge_inplace` | только E8: `sort` дельты → `unique` дельты → `std::inplace_merge` с отсортированными локальными → `unique` |
| `merge_union` | только E8: `sort` дельты → `unique` дельты → `std::set_union` в новый вектор → `swap` |

## Методология (как на слайде contract)

- **В таймере — вся операция**: `reserve`, вставки, выгрузка в вектор, деструктор таблицы
  (для radix — аллокация и освобождение буфера).
- **Вне таймера**: свежая копия входа (`assign` в заранее зарезервированный буфер) и проверка.
- **Проверка корректности после каждого вызова**: результат сортируется (вне таймера) и
  сравнивается с эталоном `sort + unique` поэлементно. Любое расхождение — `exit(2)`.
  Перед замерами `--selftest` гоняет крайние случаи: пустой вектор, один элемент, все равны,
  `0` и `UINT64_MAX`, разные N, U, порядки и плотные ключи.
- **Входы**: U различных ключей — первые U выходов splitmix64 (различны по построению:
  финализатор splitmix64 — биекция на `uint64`), каждый ключ встречается ≥ 1 раза,
  остальные N − U позиций — случайные ключи из тех же U, затем случайная перестановка.
  Seed фиксирован (17) и смешивается с номером входа, N и U.
- **Пул из P = 64 разных входов** (генерируются лениво, вне таймера). Входы идут по кругу.
- **Пакеты**: при малых N до таймера готовится K = clamp(65536 / N, 1, 64) копий разных
  входов, и таймер охватывает K вызовов подряд (для N ≥ 64K — один вызов на замер).
  Рабочий набор пакета ≤ 512 КБ.
- **Чередование**: в каждом повторе все алгоритмы получают те же входы, порядок алгоритмов
  циклически сдвигается.
- **Блоки**: 1 прогревочный блок отбрасывается, затем 7 блоков (E5, E6 — 9). В блоке каждый
  алгоритм обрабатывает не меньше 2^21 элементов (E5 — 2^20), минимум один вызов.
  В CSV — медиана, min, max по блокам и все значения блоков.
- **нс/эл** = суммарное время / суммарное N.
- Процесс закреплён на ядре 2 (`taskset -c 2`), каждая конфигурация — отдельный процесс.
- Флаги: `-std=c++20 -O3 -DNDEBUG`, без `-march` (базовый x86-64, в Abseil — SSE2, группа 16).
- Счётчики производительности недоступны: в госте KVM нет виртуального PMU
  (`perf_event_open` для `branch-misses` / `cache-misses` → `ENOENT`, см. `results/perf_probe.txt`).

## Как собрать и запустить

```bash
./build.sh            # Abseil 20260817.0 (клон, если ABSL_SRC не задан) + 3 бинарника + selftest
./run.sh s1           # все эксперименты, метка сессии s1 (≈ 7 мин)
./run.sh s2 E1 E2     # выборочно
python3 summarize.py  # сводные таблицы Markdown из results/*.csv
```

Готовые исходники и сборку Abseil можно подставить: `ABSL_SRC=… ABSL_GCC=… ABSL_LIBCXX=… ./build.sh`.
Ручной запуск одной конфигурации:

```bash
taskset -c 2 build/bench_gcc --n 1048576 --u 524288 --algs sort,uset --order random --keys random
```

Параметры: `--n`, `--u` или `--ufrac`, `--keys random|dense|e8`, `--order random|runs|sorted`,
`--algs`, `--blocks`, `--warmup`, `--work` (элементов на алгоритм за блок), `--pool` (P разных
входов), `--batch` (K буферов до таймера; 1 = один буфер, вход восстанавливается перед каждым
вызовом), `--nlocal` (E8), `--seed`, метки `--exp --session --variant`.

## Эксперименты

| | что | конфигурации |
|---|---|---|
| E1 | N = U = 2^20 | все алгоритмы × 3 связки |
| E2 | кривая U = N/2, N = 2^4 … 2^22 | GCC: все 4 алгоритма; libc++: sort, uset |
| E3 | N = 2^20, U/N = «все равны» (U = 1), 1%, 10%, 50%, 100% | все алгоритмы × 2 связки |
| E4 | N = 2^20, U = N/2, порядок: случайный / сериями одинаковых / отсортированный | все × 2 |
| E5 | «бенчмарк врал»: sort+unique (и radix как контроль), N = 1024, U = 512, разные P и K | 2 связки |
| E6 | sort, все ключи равны, N = 2^20 | 3 связки |
| E7 | плотные id 1..U (перемешаны, N = 2U) против случайных 64-бит, N = 2^20 | все × 2 |
| E8 | локальные 2^20 отсортированных уникальных + дельта 2^16 (U_дельты = 2^15, половина уже есть в локальных) | 6 алгоритмов × 2 |
| E9 | доп.: куча на прозрачных huge pages (`GLIBC_TUNABLES=glibc.malloc.hugetlb=1`) | E1 и U = N/2 × 2 |
