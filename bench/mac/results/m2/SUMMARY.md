# M2 Pro против Xeon VM — сводка прогона m2 (12.10.2026)

M2 Pro (Mac14,10), macOS 27.0.1, Apple clang 21 + системная libc++, QoS userInitiated (P-ядро), если не сказано иное.
Xeon — E1–E11 из `bench/results/summary.md` и `prep/research/deep/*.md` (gcc 13 / libstdc++, если не сказано иное).
Всё на один элемент входа.

## 1. Первый замер, N = U = 2^20

| | M2 | Xeon |
|---|---|---|
| sort + unique, нс | 19,3 | 83,5 |
| unordered_set, нс | 55,2 | 260,3 |
| хеш / sort | **×2,86** | ×3,12 |
| flat_hash_set, нс | **18,5** | 42,6 |
| radix + unique, нс | 7,5 | 40,8 |

Прежнее M2-число flat 11,7 (сохранённое наблюдение V9, другой харнесс) этим прогоном не подтверждается:
в общем харнессе flat на M2 ≈ sort (18,5 против 19,3), на Xeon — вдвое быстрее sort.

## 5. Аллокатор и фазы, U = N

| | M2 | Xeon |
|---|---|---|
| вставки / выгрузка / деструктор | 30,3 / 13,5 / 11,8 (55 / 24 / 21 %) | 102 / 60 / 67 (44 / 26 / 29 %) |
| std → pmr-буфер | 55,1 → 35,4 (**×1,56**) | ×2,5 |
| pmr → flat | 35,4 → 15,6 (×2,3) | ×4 |
| модель: чтение / malloc / чтение + malloc | 4,6 / 6,6 / **23,4** (сумма 11,2, ×2,1) | 13,3 / 21,3 / 59,6 (сумма 34,6, ×1,7) |
| модель: ячейка → узел / + malloc | 8,5 / 37,6 | 23,2 / 91,5 |

Окно (window2.csv). С nop на P-ядре чтения так и не перестали перекрываться (время = поток nop, ≈6 за такт):
пустые команды окно не занимают. С независимыми add (пишут регистр): на P-ядре время на чтение доходит до задержки
памяти (≈100–107 нс) при F ≈ 450 → окно ≈ 400–450 команд; на E-ядре — уже при F ≈ 100 (≈360 нс) → окно ≈ 100.
На Xeon (этот же код, наполнитель lea) — ≈250, с nop — ≈500: настоящим командам не хватает регистров раньше, чем места.

  8 — 12,3, 16 — 15,2.

  у sort 2,45, у хеша **0,52** (на P — 3,18 и 1,92).
